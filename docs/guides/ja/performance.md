## 解析にかかる時間を知る

米国とカナダの住所は約10マイクロ秒で解析でき、以前の200倍以上の速さです。以前は、通りの種類・州・方位の表から作る正規表現を住所ごとに作り直しており、時間はそこに費やされていました。今は最初に使うときに一度だけ作ります。ほかの国はもともと速く、変わっていません。

| コーパス（1秒あたりの住所数、大きいほうが速い） | 変更前 | 変更後 |
| ---------------------------------------------- | ---: | ---: |
| 米国（1,082件）                                |    450 | 109,415 |
| カナダ（508件）                                |    460 | 98,921 |
| 日本（1,101件）                                | 73,656 | 82,656 |
| オーストラリア（258件）                        | 237,335 | 263,893 |
| 英国（175件）                                  | 203,042 | 198,684 |
| ドイツ（144件）                                | 198,451 | 178,182 |
| フランス（186件）                              | 104,799 | 134,949 |

米国とカナダ以外の国で数値が違うのは、測ったときのマシンの状態によるもので、その国に加えた変更によるものではありません（同じノートパソコンで続けて2回測り、別にもう1組測っても同じ状況でした）。プロセスで最初の解析だけは遅く、約20ミリ秒かかります。エンジンが各パターンを最初に実行するときにコンパイルするためです。

## importにかかるものを知る

| 入口                | minify後（変更前） | minify後（変更後） | gzip後（変更前） | gzip後（変更後） |
| ------------------- | -------------: | -------------: | -----------: | -----------: |
| `.`（ルート）       |        597,494 |        431,260 |      105,712 |      101,758 |
| `./jp`              |        332,967 |        242,405 |       60,583 |       57,463 |
| `./au`、`./gb`、`./de`、`./fr` |  変更なし |       変更なし |     変更なし |     変更なし |
| `./element`         |        670,085 |        503,770 |      133,035 |      130,080 |

単位はバイトで、esbuildでバンドルしてminifyし、gzipのレベル9で圧縮したものです。`pnpm size`と同じ測り方です。新しく起動したNodeプロセスでルートをimportする時間は、約41ミリ秒から約20ミリ秒に、`/jp`は約25ミリ秒から約15ミリ秒に減りました。

## 何を使うと何が読み込まれるかを知る

- ルートは1つの関数で米国・カナダ・日本の住所を読むので、3か国の表を含みます。日本の住所だけを読む場合は、米国の通りの種類を含まない`/jp`をimportできます。
- オーストラリア、フランス、ドイツ、英国はそれぞれ別の入口で、ほかの国の表を含みません。ルートはこれらをimportしないので、使う側が`countries`に渡します。
- 最大の2つの表、日本の市区町村と米国・カナダの地区は、1行に1件ずつのパック形式のテキストで保存されます。同じ行をオブジェクトで書くよりずっと小さくなります。地区は施設の所在地を最初に調べるときに展開し、日本の検索用の索引は日本の住所を最初に読むときに作ります。
- 日本の表の展開には副作用がないと印を付けてあるので、日本の表を読まないビルドからは、バンドラーがそれを取り除けます。

解析は同期のままなので、必要になったときに表を取得することはできません。ルートを国ごとの入口に分けると`parseLocation`が読む内容が変わるため、分けていません。

## 自分で測る

```sh
pnpm bench
```

`pnpm bench`はパッケージをビルドし、各国のコーパス（`test-data/corpus`）の解析速度、新しく起動したプロセスが入口をimportして住所を1件解析するまでの時間、各入口の大きさを表示します。`node scripts/benchmark.mjs --json`は同じ内容をデータとして出力します。

## 速さを保つ

- 表から作る正規表現は、`src/parsers/standard/patterns.ts`かモジュールのトップレベルで一度だけ作り、住所ごとに呼ばれる関数の中では作りません。
- ソースファイルは1つにつきコード500行以内にします（`pnpm check:size`）。デモのスクリプトも同じです。
- 解析の段階を変える前後に`pnpm bench`を実行します。
